# 本机模型实测 · 2026-09-28

**结论：Qwen3.5 9B 可以作为这台机器上的学习基线。短任务响应符合要求；存在指令遵循失败与内存压力，需要在后续练习中验证和控制。当前结果不证明完整业务 Agent 已可靠。**

## 配置

- Apple M5，24GB 统一内存，10 核 GPU；网站与浏览器同时运行。
- Ollama 0.34.4，模型 `qwen3.5:9b`，Q4_K_M。
- 模型摘要：`6488c96fa5faab64bb65cbd30d4289e20e6130ef535a93ef9a49f42eda893ea7`。
- 8192 上下文、单并发、thinking 关闭、temperature=0.2、输出上限 256 tokens。
- 未接云端模型。所有测试输入都是合成文本，不含真实个人数据。

## 性能与内存

| 项目 | 本次观察 |
|---|---|
| 首次短任务总耗时 | 5.864 秒，其中模型加载 4.828 秒 |
| 60 次短任务总耗时中位数 | 0.780 秒 |
| 除首次加载外的短任务中位数 | 0.775 秒 |
| 生成速度中位数 | 20.84 tokens/秒 |
| 工具调用请求生成 | 约 1.99～2.50 秒 |
| 两条自然语言回复 | 2.527 秒、3.022 秒 |
| Ollama 报告的载入大小 | 约 5.67GB，100% GPU，8192 上下文 |
| 系统交换空间 | 加载前 0；测试中观察到约 3.1GB 使用，结束时约 3.0GB |

Ollama 载入大小不是整台机器的内存占用，也不包含所有应用和系统开销。本次响应仍然较快，但出现交换空间占用，不能称为完全没有内存压力。交换空间占用也不单独证明持续频繁换页；本次没有做长时间压力测试。建议先单会话、8K 上下文，用完卸载模型，不以 27B 或长上下文作为起点。

## 能力结果

20 条固定合成用例，每条运行三次，共 **57/60 通过**。这是 19/20 个不同用例通过，不是 60 个独立任务样本，也不是生产成功率。

- 范围内意图分类、字段提取、缺失信息、候选歧义、依据回答和状态规则：本次对应检查通过。
- 工具选择：明确订单编号、用户改口后编号选择、缺编号追问，三类均重复通过。只验证工具名与参数，没有执行工具。
- 缺编号回复经人工抽查：确实追问订单编号，没有宣称完成。
- **唯一失败用例重复失败三次**：分类器应把“写一首关于月亮的诗”判为 clarify，模型却在 answer 字段直接写了诗。结构合法，但语义错误。

这个失败涉及任务边界和指令遵循；尚未通过对照实验隔离提示组织与模型能力各自的影响，不能直接认定只需修改措辞。原始输出已保留，不以重跑或修改判定标准掩盖失败。后续可以把它作为一个小练习，比较输入组织、限定标签校验与提示变化。

两条额外自然语言检查未计入 57/60：

1. 订单 3 已发货但物流单号缺失：回复正确说明已发货、1 个杯子，并说明无法获知具体物流与位置。
2. 两笔杯子订单、用户只说“改到上海”：回复先请求确认是哪笔订单，没有宣称修改成功；完整地址仍需要后续收集。

## 如何解读

现在可以练习提示设计、模板参数化、路由、输出校验、短上下文和少量工具调用。分类结果必须经过允许标签检查，重要动作继续由业务程序保证权限和可靠写入。

测试中的结构化输出由 JSON schema 辅助约束，格式正确不能归功于提示词本身，也不保证业务正确。长对话、多步写入、多并发与生产使用尚未验证。工具定义、提示与模型一旦变化，应复跑用例。
