# 拾物商店：业务基线

Python 3.13 + Django 5.2.17 + SQLite；服务端页面搭配少量原生浏览器脚本，不需要 Node.js。页面和 API 共用 `src/shop/services.py` 中的业务逻辑。

## 已实现

- 演示用户登录、退出；用户与管理员权限分离。
- 商品列表、搜索、分页与详情；管理员创建、修改、上下架和调整库存。
- 收货地址创建、修改；历史订单保留独立地址快照。
- 创建订单、模拟支付、取消、修改未发货订单地址；管理员模拟发货。
- HTTP 查询与写入接口；登录会话、CSRF 校验、归属检查、字段检查。
- 乐观版本检查、事务更新、幂等编号、成功操作记录与结果查询。
- 固定种子模拟数据；页面内 AI 聊天面板连接独立空服务。

## 启动与维护

已在本机安装独立 `.venv`。普通启动：

```sh
cd /Users/colin/code/my/agent-learning/business-demo
make run
```

打开 http://127.0.0.1:8000 。`user01 / demo12345` 为普通账户；`admin / demo12345` 为管理账户。

首次重建环境时：

```sh
make setup
make seed
```

`make seed` 不覆盖已有数据。`make reset` 明确清空并恢复基线。自定义规模：

```sh
.venv/bin/python manage.py seed_demo --reset --yes --seed 20260928 --orders 1000
```

默认种子为 20260928，固定时间基准为 2026-09-01 09:00（上海时区），默认 500 笔订单。相同参数下业务记录编号、状态、金额、地址和创建时间一致；密码哈希与登录会话不属于可复现业务数据。

`make check` 检查代码格式及 Django 配置；`make test` 在独立测试数据库运行后端测试，不修改日常数据库。修改 Python 或模板后重启服务；静态文件修改后刷新浏览器。

配置可复制 `.env.example` 为 `.env`，启动命令会加载它。不需要设置密钥：首次运行会生成被 Git 忽略的 `.local-secret`。如直接调用 manage.py，自行导出环境变量；`.env` 不会被 Django 自动读取。数据库默认是项目内 `db.sqlite3`。重置命令默认作用于该库；如另设 `DEMO_DATABASE`，须在运行管理命令前导出对应值。

开发服务器的 `--insecure` 仅用于在 DEBUG 关闭时提供本地静态资源，不关闭登录、CSRF 或权限检查。

## 手机浏览器访问

手机与 Mac 连接同一 Wi-Fi。在 macOS「系统设置 → Wi-Fi → 当前网络详情」查看 Mac 的局域网 IP，然后执行（将示例 IP 换成当前地址）：

```sh
cd /Users/colin/code/my/agent-learning/business-demo
make run-lan DEMO_LAN_IP=192.168.1.10
```

手机打开 `http://192.168.1.10:8000`，使用同一组演示账户登录。手机上的 `127.0.0.1` 指手机自身，不能用于访问 Mac。保持启动终端打开，Ctrl+C 停止该服务；网络或 IP 变化后用新地址重新启动。如果无法连接，检查两台设备所在网络及 macOS 防火墙是否允许 Python 接收连接。

此入口仅监听指定的局域网地址，并将该地址加入 Django 允许的主机列表。默认 `make run` 和根目录的 `启动网站.command` 仍只监听本机。局域网访问用于可信网络中的模拟业务练习，登录、CSRF 和业务权限校验继续生效。AI 助手仍由网站服务端转发到本机 8001，手机无需连接 Agent 端口。

手机布局包含三列导航、单列商品与表单、带字段标签的订单及操作记录、适配窄屏的确认弹窗和消息提示。输入框使用 16px 字号，手机号使用电话键盘。已在浏览器中检查 320/390/768/1280px 下的主要用户页和管理页，未发现页面横向溢出；未在实体手机上测试。页面写操作的随机幂等编号兼容局域网 HTTP。

## 业务规则

1. 订单属于登录用户。用户编号不接受模型或请求自行指定；管理员的发货和商品维护权限由服务端判断。
2. 创建订单必须使用本人完整地址、有效上架商品。每单 1～20 个不重复商品，每个数量 1～99。服务器读取价格并计算总价，不信任客户端金额。
3. 下单占用库存；取消待支付或待发货订单归还库存。已模拟支付订单取消时视为同步完成模拟退款，不产生真实资金变动。
4. `pending_payment → paid → shipped`；`pending_payment/paid → cancelled`。已发货、已取消订单不能改址或取消。
5. 修改地址簿不会追溯改变订单。修改某笔订单需明确选择本人地址，并提交订单当前 `version`。
6. 写操作须携带幂等编号；同用户同编号同参数返回原结果，同编号不同参数拒绝。记录与业务变更同事务提交，失败全部回滚。
7. 超时不等于写入失败。根据操作编号核查，再用原编号和原参数重试。查询不到记录也不能立刻断定此前请求永远不会完成。
8. 订单状态校验和版本更新在事务内完成；SQLite 写入先获取写事务，避免两个请求同时消费旧状态。繁忙时返回受控冲突，不适合作为高并发生产数据库。
9. 手机号只是演示格式检查：以 1 开头的 11 位数字。省市区要求非空，不接入真实地理编码服务。

固定数据是一个期初业务快照：商品库存表示当下可售库存，历史订单已单独存在；取消历史未发货订单会归还其数量。不是完整的历史库存流水账。

## 边界

API 支持确定的业务操作，但不内置 Agent 的意图识别、对话确认、工具编排或执行恢复。网站表单提供人工确认；未来 Agent 的确认必须绑定具体操作和参数，由程序管理，不能依赖模型说“用户已确认”。

模拟支付与物流、本地账户、SQLite 和开发服务器用于学习。未接入真实支付、短信、物流或公共互联网部署。写入记录保存模拟业务快照，普通运行日志不打印请求体、密码或密钥。
