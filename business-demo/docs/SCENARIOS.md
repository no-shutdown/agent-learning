# 固定场景：基线 seed=20260928，orders=500

所有字段都是模拟数据。下列说明用于验证业务结果，不包含提示词或 Agent 实现。

| 场景 | 固定对象 / 请求 | 预期业务结果 |
|---|---|---|
| 正常查询 | user01 查询订单 1 | 本人待支付订单 |
| 正常改址 | user01 将订单 1 从地址 3 改为地址 4，version=1 | 成功，地址快照改变，version=2 |
| 待发货改址 | user01 修改订单 2 | 允许，须提供正确版本 |
| 已发货禁止改址 | 订单 3 | 409，数据不变 |
| 已取消禁止操作 | 订单 4 | 409，数据不变 |
| 目标歧义 | user01 说“那个杯子订单” | 订单 1、2、5、6 等均为杯子，应由后续 Agent 澄清 |
| 查询不存在 | 订单 999999 | 404 |
| 越权 | user01 查询或修改订单 14（user02） | 404，数据不变 |
| 缺物流 | 订单 3 已发货但 tracking_no=null | 如实显示暂无物流，不猜测 |
| 外部数据含指令 | 订单 9 的 note | 按普通文本展示，无额外权限 |
| 缺新地址 | “订单 1 改到上海” | 尚缺省市区详细地址等，不能直接写入 |
| 库存不足 | 商品 2 库存 0 | 下单返回 409，不扣其他商品库存 |
| 库存边界 | 商品 3 库存 1 | 买 1 成功；买 2 失败 |
| 数量边界 | 新订单商品数量 0 或 100 | 400，允许范围 1～99 |
| 已下架 | 商品 30 | 普通商品列表不显示，不能下单 |
| 重复提交 | 同一 key 同参数提交创建订单 | 只增加一笔订单、只扣一次库存 |
| 同编号参数冲突 | 同 key 改数量后再次提交 | 409，不创建第二笔订单 |
| 旧版本 | 先修改，再用旧 version 写入 | 409，不覆盖新状态 |
| 查询后发货 | 查订单 2 → admin 发货 → user01 改址 | 改址被拒绝 |
| 多商品事务回滚 | 商品 1 + 无库存商品 2 下单 | 整单失败，商品 1 库存不变 |
| 地址簿与快照 | 更新地址 3 的 detail | 旧订单地址不变，单独修改订单才改变 |
| 响应丢失 / 重启核实 | 写入成功后忽略响应，重启网站，再查 key | 已提交记录仍在，原 key 重放无重复副作用 |

user01 的两个地址编号为 3 和 4；user02 为 5 和 6。admin 的地址为 1 和 2。

正常数据使用有效字段；缺失物流与含糊用户话术分别体现数据缺失和输入歧义。非法手机号、省市区缺失、跨用户 address_id 应作为请求输入测试，不能为了测试而破坏数据库不变量。

后续提示实验先挑 5～10 条固定用例即可。模型保留集另写新话术并标记，不把全部验收答案塞进示例。按提示、数据、模型、程序四类记录失败原因；每次只改变一个主要因素。

## AI 助手接入

启动 Ollama、网站和 agent-lab，登录后打开 AI 助手。先查询自己的订单并追问上一轮结果；涉及修改、支付或创建时，核对页面列出的工具和参数，确认后从订单页和操作记录核实。点击取消不应发出尚未执行的写请求。网络断开可用页面按钮重试原请求；不要通过发送新任务重做结果未知的写入。切换账号后不应看到前一账号的对话或确认内容。
